## Intro

zsh is a type of shell among many others and the following will be a guide on organizing what goes into each of the zsh configuration files.

> [!NOTE] 
> There are other components one of which is `~/.zlogin`, which will not be covered here because I don't think it's as important. 

## Load Order

This is the whole reason the files differ. zsh reads them in this order:

```text
~/.zshenv  →  /etc/zprofile (path_helper)  →  ~/.zprofile  →  ~/.zshrc  →  ~/.zlogin
   always            login only              login only     interactive
```

Two consequences do all the work:

- `~/.zshenv` is the only file a **non-interactive, non-login** shell reads — scripts with a zsh shebang, cron, tools spawning `zsh -c`.
- `path_helper` runs **after** `~/.zshenv`. It rebuilds `PATH` from `/etc/paths` and `/etc/paths.d`, putting those first, then appends whatever was already set.

## .zshenv

Loaded for every zsh invocation. Put **plain environment variables** here — they survive untouched, because `path_helper` only rewrites `PATH`. Reason why you shouldn't set `PATH` here as MacOS overrides it.

Because `path_helper` demotes it, `/opt/homebrew/bin` set here would lose to `/usr/bin`, and Apple's `python3` would shadow the Homebrew one.

## .zprofile

macOS starts a login shell for each new terminal window, so this runs in practice for every session. It loads after `path_helper`, so prepends stick.

`PATH` goes here — Homebrew's own install instructions say the same:

```shell
eval "$(/opt/homebrew/bin/brew shellenv)"   # prepends bin+sbin, sets HOMEBREW_*/MANPATH/INFOPATH
export PATH="$HOME/.local/bin:$PATH"
```

The tradeoff: non-login shells don't read this, so a zsh script gets the system `PATH`. If that ever matters, re-prepend inside `~/.zprofile` — don't move `PATH` to `~/.zshenv`.

## .zshrc

Interactive-only: aliases, prompt, completions, and tools needing `zle` (e.g., fzf, zoxide, nvm). It also loads after `path_helper`, so `PATH` set here *works* — but it's wrong on principle, since a non-interactive login shell would miss it.

> [!note]
> An interactive shell reads commands directly from user input (TTY), while a non-interactive shell runs scripts or automated tasks in the backround without user interaction.
